# Android / iOS 機能対応の目標

> 過去の調査・実装・比較の記録。現行の製品仕様・OS別方針・構造は [設計正本](design-doc.md) に集約済み。本書の当時の目標や案を、現行の仕様・未採用案の実行指示として扱わない。

2026-09-06。ユーザー方針: iOS で提供している機能は基本的に Android でも提供する。初期設計書だけでなく現在の `todo.md` の実機QAとソースを基準にする。古い設計書で対象外だった Web サイトも、現在は対応目標に含める。

製品実装を `android-lab/product` に追加した。[実装結果](android-product-results.md)と[実装TODO](android-implementation-todo.md)が最新の進捗。下表は比較試作時点の差分を履歴として残したもの。Web・カテゴリの対応範囲、OS・端末検証の残件は最新資料を参照。

| iOS の機能 | Android での方針 | 今回の範囲 / 未解決事項 |
| --- | --- | --- |
| 対象アプリ選択 | 起動可能なアプリ一覧を選択 | 試作は1つ。本番は複数選択。システムアプリ・ホーム・設定等の除外を拡充する |
| 今すぐロック | 同じ時間区間の判定を使用 | 試作あり。5〜300秒に限定 |
| N分後の予約 | 永続化＋アラーム＋検知時再照合 | 試作あり。予約待ち0〜300秒 |
| 指定日時の予約 | 同じ開始・終了時刻モデル＋日時入力 | 保存モデルは対応。日時UI・長時間運用は未実装 |
| 曜日指定・日跨ぎの繰り返し | iOS の曜日・タイムゾーン・次回生成仕様を移植 | 今回は未実装。DST と時計変更のテストが必要 |
| 開始前の予定編集・削除 | iOS と同じ条件で許可 | 試作では比較条件を固定するため予約中も変更不可。本番では解消する差分 |
| 開始後の短縮・解除・対象削減禁止 | UI と保存層の両方で禁止 | 試作はウィンドウの上書きを拒否。OS 権限取消まで禁止しない |
| 親の繰り返し変更で現在のロックを解除しない | ActiveLock を親から分離 | 未実装。iOS のテストケースを移植する |
| 重複するロックの拒否と説明 | iOS と同じ重複規則 | 試作は1件のみ。本番の複数予約で区間重複を実装 |
| 終了時刻で自動解除 | 検知時にも終了判定 | 試作あり。Doze・再起動を含めて評価 |
| ブランド付き Shield・解除予定表示 | Android のブロック画面で再現 | 試作は簡易表示。本番の熊画像・対象名・日本語/英語を移植 |
| アプリ・端末再起動からの復元 | ローカル保存・起動受信・サービス復旧 | Bの前面アプリ再判定を追加。接続前から開いている対象への遮断・自然終了をエミュレーターで確認。端末再起動全体はSystem UI応答停止で入力検証未完了。[追試結果](android-recovery-results.md) |
| 最近使った対象3件・ピン・削除 | パッケージ集合を参照する履歴 | 未実装。OS依存の障害は現時点では見つかっていない |
| 権限取消時の復旧画面 | 必要権限と接続状態の表示 | 試作は状態・設定導線あり。本番では設定手順を整理 |
| 端末内 Diagnostics | 実験ログから運用診断へ整理 | JSONL・アプリ内表示あり。製品版のログ保持と個人情報最小化を仕上げる |
| アカウント不要・端末内保存 | 維持 | 試作もネットワーク権限なし |
| 日本語・英語 | iOS 文言を移植 | 試作は日本語中心。リソース化・英語は本番工程 |
| Web サイト選択・ブロック | 対応目標を維持、別検証を必須にする | 未実装。Accessibility でブラウザURLを検知する場合は対応ブラウザ・シークレット・カスタムタブを評価。VPN/DNS方式なら既存VPNとの競合や通信と画面制限の違いを評価 |
| カテゴリ選択・カテゴリ単位の制限 | 選択したカテゴリを対象集合に展開する仕組みを検討 | Apple の Screen Time カテゴリ/トークンは流用不可。Android 側の分類の精度、未分類アプリ、新規インストール時の扱いを検証 |

アプリ単位の試験が良好でも、Web サイト・カテゴリまで同等に提供できるとは判断しない。この2項目は Android の公開仕様を決める前の独立した検証ゲートにする。
