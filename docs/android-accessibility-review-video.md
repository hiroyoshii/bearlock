# Google Play ユーザー補助 API 申告動画

申請するバージョンと同じ内部テスト版で撮影する。目安は 2〜3 分（Google の指定時間ではない）。動画は未作成。この文書は撮影台本。

## 撮影前

- Play ストアから申請対象版をインストールし、バージョンコードを記録する。
- 実行中のロックが終了している状態で、Android 設定から Bear Lock のユーザー補助をオフにする。アプリのデータ削除は不要。
- 「アラームとリマインダー」は先に許可しておくと撮影が短くなる。
- ロック対象には撮影後 15 分使わなくてもよいアプリ（例: 電卓）を使う。
- 通知に個人情報が映らないようにし、端末の画面録画を開始する。マイクは任意。

## 撮影順

1. ホーム画面から Bear Lock を開く。初回案内が出る場合は「はじめる」。
2. 「ロック対象を選ぶ」で電卓などを選択し「保存」。今すぐのロックを 15 分に設定し「ロック開始」。
3. 権限不足の案内で「設定へ」→「ユーザー補助を設定」。通常の操作から開示に至る経路を映す。
4. 「ユーザー補助の使用について」の本文を 10〜15 秒表示。スクロールが必要なら全文が読めるようにゆっくり動かす。
5. 「同意しない」を押し、アプリの準備画面に戻ることを映す。
6. 再び「ユーザー補助を設定」。同じ開示が再表示されることを映し、「同意して設定へ」を押す。
7. Android のユーザー補助設定で Bear Lock を開き、有効化して OS の確認にも同意する。項目名は端末により「インストール済みアプリ」「ダウンロードしたアプリ」など異なる。
8. Bear Lock に戻り、「接続済み」を映す。「確認に戻る」から対象・終了時刻を確認して「ロック開始」。
9. ホーム画面に戻り、選択したアプリを開く。Bear Lock のブロック画面が表示され、対象アプリを操作できない状態を 5〜10 秒映す。
10. 録画終了。15 分の自然解除まで収録する必要はない。解除の場面を追加するなら、待機部分を省略したことを字幕で示す。

## 音声または字幕の例

開示表示時:

> Bear Lock は AccessibilityService API で前面アプリの識別情報を読み、ユーザーが選んだアプリを設定時間中ロックします。Web 制限中は対応ブラウザのアドレス欄も読みます。URL や閲覧履歴は保存・送信せず、判定は端末内で行います。

拒否時:

> 同意しない場合は権限設定へ進みません。後から同じ開示を再表示できます。

ロック表示時:

> ユーザーが選択した対象アプリを検出し、ブロック画面を表示しています。

Web 制限も申告する場合は、追加で対象ドメインを設定し、対応する Chrome または Firefox の通常タブでその URL を開いてブロックされる場面を撮影すると、用途を説明しやすい。ブラウザ自体のアプリロックと区別できるようにする。

## 提出

YouTube の限定公開など、審査担当がログインやアクセス申請なしで再生できるリンクを用意する。シークレットウィンドウで再生できることを確認し、Play Console の「認識しやすい開示」の動画リンク欄に貼る。ストア掲載情報の宣伝動画欄とは別。

権限を ADB で付与したテスト、開示画面だけの静止画スライド、デバッグ用の疑似ロック画面は、実際の同意・許可・機能利用の操作動画の代わりにはしない。
