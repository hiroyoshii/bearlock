# Android UIレビュー：iOSスクショとの比較

[修正結果と新しいスクショ](android-ui-refresh-2026-09-08.md)に対応内容を記録。以下は修正前のレビューを保存しています。

2026-09-08。UI修正前の問題一覧。OSの制限能力ではなく、配置・余白・文字・操作部品を対象にする。

## 結論

画面の構成と素材は近づいたが、部品の配置ルールが揃っていない。特に「上部の対象カードが大きい」「小さなボタン内は窮屈」「重要度の低い文字まで太い」「左右の操作数でタイトル位置が変わる」が重なっている。余白を一律に減らすと小ボタンがさらに窮屈になるため、情報密度と部品内部の余白を別々に直す。

以前の「小画面・文字拡大対応済み」は操作可能性の対処までで、見た目の品質まで完了したとはいえない。文字150%の「カテゴリ」の途中改行は既存の証拠画像に残っている。

## 比較の条件と限界

- 主比較は [既存ギャラリー](../ANDROID_SCREENSHOTS.md) の日本語5画面と英語ホーム。左iOS・右Android、原寸1284×2778。Androidは428×926dp、文字100%。
- ギャラリーのiOS画像は固定された過去のCI画像。現在の [iOSホーム](../ci-screenshots/app-store-ja/home.png) と [繰り返し](../ci-screenshots/app-store-ja/composeRepeat.png) も目視確認し、主要構成が同じであることを確認した。日付や時刻の違いは不具合に数えない。
- Androidは2026-09-06保存のDebug比較画像と通常操作のスクショを使用。今回の実機・Play配布版を新しく撮影したレビューではない。
- iOSのホームは「保存済みの選択」というプレビュー表示、Androidはアプリ・カテゴリ・Web件数を表示。カードの高さの差すべてをAndroidの余白バグと断定しない。
- 繰り返し・ロック中の比較画像は専用プレビュー。画面上端の位置をそのまま実際のホーム画面の不具合とは扱わない。
- 静止画から操作中の揺れ・スクロールの飛びは確定できない。下記の「コードから確認できる要調査項目」と区別する。

セットアップの構成は比較的近く、大きな優先修正は見つからない。ヒーローの上下位置・角丸・説明の行間は差があるが、主操作の収まりより優先する根拠は薄い。[セットアップ比較](qa/android-ui-parity/compare/ja/setup.png)

予定一覧の日付はiOS側でも不自然な位置で折り返している。Android側は小さな文字で1行に収まっているが、日時の長さが異なるため「Androidは切れている」とは断定しない。長い日時・文字拡大で、日付と時刻のまとまりを壊さない改行を追加検証する。

## 修正順と再レビュー条件

1. UI-16の画面全体再生成を計測し、操作中の位置を安定させる。
2. UI-11〜13の折り返し・タイトル配置を直す。
3. UI-01〜04の対象カード、モードボタン、文字階層を整える。
4. UI-05〜10、14〜15の余白・部品の見た目を調整し、UI-17を実画面で検証する。

次の比較は同じ対象数・同じ日時文字列・同じ言語と文字サイズで行う。通常ホームの今すぐ／後で／日時／繰り返し、選択詳細展開、実ロック中、実確認シート、設定、対象選択を撮る。標準幅と320dp、文字100%と150%を含める。文字拡大時は「スクロールがないこと」ではなく、読めて操作へ到達できることを条件にする。

静止画の見た目の合格と、動画での位置・フォーカスの安定を別に確認する。ブロック時の対象アプリのちらつきやランチャーアイコンの制約は、このUIレビューの範囲外。
