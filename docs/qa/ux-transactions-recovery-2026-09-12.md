# 保存・確認・復旧の修正

対象はUXレビューの優先グループ1・2。初回権限導線全体や予約一覧の再設計は対象外。

- 両OSの有効状態を編集ドラフトにし、曜日・時間と一括保存。キャンセルでは反映しない。
- 即時・遅延の確認は確定／開始からの相対時間。繰り返しは曜日・時刻・継続時間。確認画面で待機しても表示した約束を変えない。
- iOSの削除に確認。対象選択は保存成功後に閉じ、失敗時はドラフトと再試行を残す。読込失敗は空選択と区別。
- Androidで保存異常・サービス未接続・予約権限欠落を区別し、正常な実行中カードを表示しない。保存異常から再読込・診断へ誘導。
- 両OSでReleaseの診断閲覧と手動共有。iOSは権限拒否／取消後もホーム・設定へ到達可能。初期画面にもサポートと診断の導線。

## 検証

Swift Core 61件成功（有効／無効の一括保存と重複検証の回帰追加）。Android Debug/Releaseビルド、単体20件、lintDebug成功。SwiftUIはLinuxで構文検査、Xcode型検査とUIテストはActionsの対象。

iOS UIテストへ削除取消、繰り返し切替取消・保存を追加。Android実操作スクリプトも変更。ただし現在接続されたAndroid端末／エミュレーターはなく実操作は未実施。

## 配布版で確認すること

1. 両OSで有効状態と時刻を変更→キャンセル→再度開いて元の状態。保存した場合は両方反映。
2. 確認画面で数分待機／一時中断してから確定。即時・遅延は表示した相対時間どおり、日時指定は固定時刻どおり。繰り返しは選択曜日・時間帯どおり。
3. iOS対象選択に書込失敗を注入して選択が残り再試行できること。読込失敗を空選択で上書きしないこと。
4. Androidサービス切断・予約権限取消からの復旧。専用テストデータで保存破損からの案内も確認。
5. iOS権限取消後のホーム・予定・設定への到達と、権限復旧後の操作。
6. Releaseで診断内容を閲覧し、ユーザーが共有先を選べること。ログ読込失敗時も問い合わせ先に到達できること。

OSの実遮断・解除は端末上で別途確認。診断は自動送信しない。
