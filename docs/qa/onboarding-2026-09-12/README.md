# 初回案内と権限導線

## 変更

トップページは熊の画像、ロックの説明、途中解除できないことと自動終了の説明、「はじめる」だけ。ここでは権限要求を行わない。初回案内を終えたら次回からホームへ。iOSの既存許可・保存データがある利用者もホームを維持する。

iOSではホームの時間・モード入力を操作でき、対象選択時に用途説明を表示。「あとで」はホームに留まり、「続ける」でScreen Timeの許可を求める。許可成功時はそのまま対象選択、拒否時はホームを維持する。Androidでは対象・時間を選んで開始／予約を押した時点で必要な設定を案内し、OS設定から戻ったあと「確認に戻る」でドラフトの確認を再開する。自動でロックを開始しない。

## 検証の区別

- iOS UI操作テストは実際のSwiftUI画面を操作するが、権限と対象Pickerはテスト用サービス。AppleのOS許可画面・実制限の実機確認を済ませたという意味ではない。
- Androidは使い捨てのAndroid 14エミュレーターで実画面とOS設定への往復を操作する。権限付与自体はテスト用adb操作を使用。メーカー固有の設定画面操作は別途実機確認。
- ストア用画像は両OSとも製品UIをサンプルデータで描画。操作試験中の画像とは分ける。

## 操作試験

1. 初回に「はじめる」が見え、権限要求なしにホームへ移動。
2. 時間・モードを変更して対象を選ぶ。
3. 権限案内を取り消してもホームと入力内容が残る。
4. 権限拒否／同意しないから再試行できる。
5. 許可／OS設定後に対象選択または確認画面へ戻る。入力した時間を保持。
6. 確認を取り消した場合はロックを開始しない。
7. 再起動でトップページを繰り返し表示しない。

実機ではiOSの実許可・拒否・設定からの復帰、AndroidのPixel/Galaxy等の設定導線、両OSの文字拡大・画面読み上げを確認する必要がある。
